# Codex 调度台提示词

方括号中填入当前任务的信息。直接在反重力对话中使用。材料可以是工作目录中的文件、测试输出或一小段观察记录。

## 编码派单

> 请在当前工作目录完成 [目标]。已有行为 [需要保留的行为]，验收方式是 [测试命令或可观察结果]。先判断影响范围、未知因素和验证成本，再把任务派给合适的 Codex 模型。结束时给我改动文件和实际验收结果。

简单修改用 `simple`（Luna / `low`）。需要在浏览器实际点击、填表或截图验收时用 `browser`（Terra / `medium`），纯前端代码修改按开发难度选档。常规开发和调试用 `standard`（Sol / `high`），省略 `difficulty` 时也用这档。困难任务用 `hard`（Sol / `xhigh`），极高难度或错误代价高时用 `exceptional`（Sol / `max`）。

首次派单可用 `model`（完整模型 ID）和 `effort` 独立覆盖，省略的参数按难度取默认值。需要更强能力时，可在 `relay_dispatch` 或编码 `resume` 显式指定 `model: 'gpt-6.2-astra'`，并配合 `effort: 'max'`。Terra 可用 `ultra`，Luna、Sol 和 Astra 最高 `max`。任务面板的列表、依赖图和详情随任务更新显示当前模型和思考等级。

会话默认用 `permission: default`，按任务 `mode` 使用 `read-only` 或 `workspace-write`，并采用 `on-request` 按需审批。用户已授权免审批且操作可在所选沙盒完成时，用 `auto`（同一沙盒 + `never`）。只有用户明确要求完全开放，或已授权需要跨工作区、联网等操作且明确涵盖解除沙盒与免审批时，才用 `full`（完全开放权限，`danger-full-access` + `never`）。选择足以完成已授权操作的最小权限。

可分别用 `sandbox` 选择只读、工作区写入或解除 Codex 沙盒，用 `approvalPolicy` 选择 `on-request` 按需审批、`untrusted` 对非可信命令请求审批，或 `never` 免审批。`mode: read` 只能用 `read-only`，禁止 `full`。面板列表、依赖图和任务头部显示当前权限，详细信息可查看完整的沙盒模式和审批策略。

> 请在我已授权的 [操作范围] 内完成 [目标]。本任务允许在当前沙盒内免审批，请用 `permission: auto` 派单。若确实需要扩大授权，先说明具体操作并征求我的确认。

## 并行拆解与依赖图

> 请把对 [实验结果或研究材料] 的复核拆成同一任务群。先并行派出只读的「原始证据核对」和 Astra Max「反例与替代解释」两项。原始证据在 [路径]，请重点核对 [分母、对照或异常样例]。邀请 Astra Max 前，先写下对 [可能解释] 的初步判断和可能过严的前提，让它用反例检验并探索原框定之外的解释。再派「汇总」节点，依赖前两项。逐一核对上游的证据并用 `accept` 写入验收备注，全部通过后由系统自动启动汇总。最后列出双方一致的发现、仍有分歧的问题和最小验证步骤。

同一批任务共用 `graphId`，用 `graphTitle` 标注任务群，用 `nodeLabel` 标注每项短名。先派上游，再在汇总节点的 `dependsOn` 填已派上游的任务 UUID 或 `requestKey`。同目录只读任务可并发，互不包含的目录可分别跑独立写任务，同目录及上下级目录的写任务会排队。点击图中节点可看证据、验收状态和排队原因。

## 阻塞交接

> 先查 [错误或失败测试] 的原始输出和已经尝试的方法。提出一个与前次不同、能被证据推翻的解释，并写明验证它需要观察什么。如果必须亲自动手，等 Codex 交出工作目录后再修改。记录结果，再交还原会话。新证据显示难度改变时可以换模型、调整思考程度。只有需要我决策或确实没有新线索时再问我。

调用 `resume` 时可单独改 `model` 或 `effort`，也可同时改。给出 `difficulty` 时，省略的参数按新难度取默认值。省略 `difficulty` 时，省略的参数沿用上一轮。

`resume` 可分别调整 `sandbox` 和 `approvalPolicy`。显式传 `permission` 时，省略项按新预设取值；省略 `permission` 时，未指定的项沿用上一轮。遇 `requestApproval` 且请求超出已授权范围时，先用 `ask_user` 并在原对话中确认授权，禁止静默升级到 `full`。

## 与 Astra Max 设计实验

`relay_discuss` 讨论和追问固定使用 `gpt-6.2-astra` / `max` 与 `default`（`read-only` + `on-request`）。

> 我想区分 [解释 A] 和 [解释 B]。已有材料在 [路径]，预算或约束是 [约束]。请反重力先给出预测，检视实验约束是否过严、两种解释是否框得太窄，再请 Astra Max 找反例、混杂因素和替代解释。选一个能区分关键解释的对照，列出观察指标、可能结果和对应解释。

## 委托子代理与 Astra Max 多轮讨论

> 发起「[讨论议题]」前，请先回到我的目标，自查你设定的前提、约束或验收标准是否过严，问题是否框得太窄。在 `position` 写下当前判断、证据、希望被挑战的前提和发散方向。用 `relay_discuss(delegate: 'subagent', ...)` 登记讨论，用 `graphId` 和 `dependsOn` 画出任务图。
>
> 给一个 `self` 子代理（`Model: 'inherit'`）任务 ID 和收敛条件，请它与 Astra Max 核对 [材料或反例]、试探哪些前提可以推翻、重构问题后有哪些替代路径。子代理严禁再派生子代理。请它先 `claim`，认领启动或 `resume` 后用 `schedule(..., TimerCondition: 'any')` 等唤醒。收敛或遇阻时，用 `handover` 写共识、证据、剩余分歧、可能过严的前提和新视角，结束本轮并向主对话汇报，省略 `schedule`。严禁子代理 `accept` 或 `cancel`。
>
> 收到交接后，请主对话亲自跳出双方争论，回到我的根本目标，深度反思自己的预设和标准。比较放宽非本质约束、推翻假设或综合新方案后的选择，再用 `accept` 写下最终定论并放行下游。仅在缺少会影响定论的关键原始证据时，用 `resume` 请 Astra 补充。

主对话负责检视自己的前提、重构问题并作出最终判断，子代理负责与 Astra Max 核对证据和试探替代路径。直系子代理已就绪且已知其对话 ID 时，可只传 `delegateOrigin` 直接绑定。正在等待认领的讨论可由主对话 `handover` 收回，子代理通知连续失败时也会回退给主对话。

## 与 Astra Max 复核结果

> 请一起复核 [结果表或原始记录]。反重力先说明观察，并自查复核口径是否过严、解释是否太窄。请 Astra Max 独立核对分母、对照和反例，寻找原框定之外的解释。对会改变结论的分歧，用原始记录追问。最后写出双方判断、证据支持的结论和最值得再测的一项。

## 与 Astra Max 比较方案

> 目标是 [目标]，约束是 [约束]，候选方案在 [路径]。反重力先给出倾向和理由，自查约束或标准是否过严，再请 Astra Max 挑战关键假设，探索放宽非本质条件后的第三条路径。追问会改变选择的分歧，最后给出推荐方案、分歧和低成本验证办法。

## 追问或验收

> 回到刚才的任务。我补充了 [新证据或文件路径]。请在原会话核对它是否改变结论。编码任务给出实际测试结果。讨论收口前，主对话重审自身前提和验收标准是否过严或狭窄，比较跳出原框定的替代路径，再写下最终定论，并交代双方观点和依据。
