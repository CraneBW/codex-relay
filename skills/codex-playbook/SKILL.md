# Codex 调度台提示词

方括号中填入当前任务的信息。直接在反重力对话中使用。材料可以是工作目录中的文件、测试输出或一小段观察记录。

## 编码派单

> 请在当前工作目录完成 [目标]。已有行为 [需要保留的行为]，验收方式是 [测试命令或可观察结果]。先判断影响范围、未知因素和验证成本，再把任务派给合适的 Codex 模型。结束时给我改动文件和实际验收结果。

简单修改用 `simple`（Luna / `low`）。需要在浏览器实际点击、填表或截图验收时用 `browser`（Terra / `medium`），纯前端代码修改按开发难度选档。常规开发和调试用 `standard`（Sol / `high`），省略 `difficulty` 时也用这档。困难任务用 `hard`（Sol / `xhigh`），极高难度或错误代价高时用 `exceptional`（Sol / `max`）。

首次派单可用 `model`（完整模型 ID）和 `effort` 独立覆盖，省略的参数按难度取默认值。任务面板的列表和详情随任务更新显示当前模型和思考等级。

## 阻塞交接

> 先查 [错误或失败测试] 的原始输出和已经尝试的方法。提出一个与前次不同、能被证据推翻的解释，并写明验证它需要观察什么。如果必须亲自动手，等 Codex 交出工作目录后再修改。记录结果，再交还原会话。新证据显示难度改变时可以换模型、调整思考程度。只有需要我决策或确实没有新线索时再问我。

调用 `resume` 时可单独改 `model` 或 `effort`，也可同时改。给出 `difficulty` 时，省略的参数按新难度取默认值。省略 `difficulty` 时，省略的参数沿用上一轮。

## 与 Astra Max 设计实验

讨论和追问固定使用 `gpt-6.2-astra` / `max`，以只读方式核对材料。

> 我想区分 [解释 A] 和 [解释 B]。已有材料在 [路径]，预算或约束是 [约束]。请反重力先给出自己的预测，再邀请 Astra Max 找混杂因素和反例。一起选一个能让两种解释给出不同预测的对照，列出观察指标、可能结果和各自对应的解释。

## 与 Astra Max 复核结果

> 请一起复核 [结果表或原始记录]。反重力先说明具体看到了什么，Astra Max 独立核对分母、对照和反例。两者意见不同就带着原始记录追问。最后分别写出双方判断、现有数据支持的结论，以及最值得再测的一项。

## 与 Astra Max 比较方案

> 目标是 [目标]，约束是 [约束]，候选方案在 [路径]。反重力先给出倾向和理由，让 Astra Max 检查最容易失效的假设。对会改变选择的分歧追问一轮，最后给我推荐方案、仍有分歧的地方和一个低成本验证办法。

## 追问或验收

> 回到刚才的任务。我补充了 [新证据或文件路径]。请在原会话核对它是否改变结论。编码任务给出实际测试结果，讨论任务保留反重力与 Astra Max 各自的观点。结论已经稳定时就结束并汇总。
